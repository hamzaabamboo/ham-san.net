# 3Dホーム — 統合要件

## 1. 目的と資料の優先順位

本人の実際の部屋を、認識できる配置と特徴物を残した最小構成の一人称ホームページにする。簡略化は物量を減らすことであり、家具を別物に変えること、粗い図形や仮素材で完成扱いすることではない。

1. 最新の所有者平面図 `owner-floorplan-v2 / 2026-09-07 15:20:59`。鍵盤スタンドとペンライト・タオル掛けが追加された2枚目を配置の原本とする。
2. 所有者の直接確認・修正。直線的な机、同一壁の2窓、左向きのPC机、発光ペンライトなど。
3. 提供された原写真3枚。家具の種類、特徴、材質、色、展示物を照合する。広角の見え方から壁角度・実寸を断定しない。
4. 下記Web参考。体験と制作工程の参考であり、実際の部屋の配置を変更する根拠にしない。
5. 現行コード・Blender・生成物。実装状態の原本であり、要求の原本ではない。不一致時に仕様を実装側へ書き換えない。

詳細配置・相対座標・原写真一覧は[room-reference-map.md](room-reference-map.md)。進行状態は[CURRENT_TASK.md](CURRENT_TASK.md)だけで管理する。本書は要件、停止履歴room-resume.mdは履歴であり進行指示ではない。

### 1.1 正規要求台帳

この節が部屋制作の要求・状態・受入れ証拠を束ねる唯一の正規チェックリストである。`room-reference-map.md`、`room-reference-books-2026-09-08.md`、`room-reference-zip-2026-09-08.md` は観察記録、`room-full-handoff-2026-09-07.md` などのhandoffは履歴であり、要求や状態を上書きしない。状態は `未検証` を初期値とし、`部分確認` は限定された原本または操作だけ、`再監査` は過去の限定証拠が最新の目視指摘で受入れ根拠にならない状態、`検証済み` は指定された全受入れ証拠が揃った状態を示す。最新の所有者確認と参照密度は、古い「最小」を疎な配置と解釈する記録より優先する。最小化は無関係な生活雑貨を省くことであり、特徴的な物量・カテゴリ・遮蔽関係を削ることではない。

## 6. 照明と仕上げ

- LIT-01: Asia/Tokyo基準で昼は昼光、夜は暖かい室内照明へ適応する。他タイムゾーンを基準にしない。
- LIT-02: 適切な空の背景・環境反射・窓からの採光・接地影を実装する。誤った壁から光が入る状態を残さない。
- LIT-03: 透明窓とすりガラス、透明展示ケースを区別する。透過材を不透明な影として描画しない。
- LIT-04: 高いゲーム品質を目指す。モデル・配置・UV・質感・照明の全てが対象で、空や露出の変更だけを完成と呼ばない。
- LIT-05: 最小限の物量と高品質は両立する要件。リアルさのために最大物量へ戻さず、最小化のために安価な仮形状へ戻さない。原写真の棚構造・椅子の曲面・布の変形を照合する形状ゲートは、照明や発光の調整では代替できない。
- LIT-06: 3Dは写真由来の自然色。HTMLは既存Atelierトークン。性能は実際の対象端末で検証し、根拠のない100%・無欠陥・AAA達成を宣言しない。
- LIT-07: 窓外は日本の住宅街が見えるスカイボックス／ワールド背景を制作する。空だけでなく住宅・屋根・街路の距離感を持たせ、窓からの目線と地平線を合わせる。視覚背景用画像と採光・反射用の環境光を区別する。昼画像を暗くするだけで夜景完成とせず、Tokyo昼夜と整合を検証する。特定住所や実在の近隣の正確な再現は要求されていない。生成資産と検証境界は[room-assets.md](room-assets.md)を参照する。
