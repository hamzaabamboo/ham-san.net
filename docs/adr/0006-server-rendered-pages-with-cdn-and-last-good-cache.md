# Data pages are server-rendered behind a CDN with a last-good fallback

Pages that read Strapi, Outline or Eventernote set `prerender = false` and are rendered per request by the Astro Node server, which runs in Docker on Ham's VM (`ASTRO_ADAPTER=node` in the `Dockerfile`; the Netlify adapter is only the local default). They set `CDN-Cache-Control` per branch: long TTLs when data loaded, 60 s or `no-store` when an upstream failed. Every upstream read goes through `withLastGood` / `withLastGoodState` (`apps/astro/src/utils/cms-cache.ts`), which serves the last successful value when a fetch throws. Content changes in the CMSes without a deploy, so static generation would go stale. The CDN in front of the server bounds upstream load, and the in-process fallback keeps pages readable through short outages. The fallback is per server instance and is lost on a cold start, so a first request during an outage still shows the page's unavailable state.
